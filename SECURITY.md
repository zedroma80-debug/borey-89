# Границы приватности

Общие room/scene/player metadata и broadcast Owlbear **не используются** для хранения и передачи листов, тайн или скрытых показателей. SDK предоставляет клиентские сведения о комнате и пользователе, но наш сервер не получает подписанного доказательства роли ведущего из этих сведений. `OBR.player.getRole()` не является серверной аутентификацией. Не следует заменять коды доступа доверием к переданному клиентом `role` или `playerId`.

Серверный администратор создаёт комнату через CLI. Для неё выпускаются пять независимых случайных кодов по 256 бит: один для ведущего и по одному для каждой профессии. Это пароли предъявителя: владение кодом даёт соответствующие права. Коды не привязываются автоматически к учётным записям Owlbear. Администратор должен проверить, кому выдать роль, и передать каждый код лично по защищённому каналу. Запрос доступа к листу контролируется сервером, а не видимостью элементов интерфейса. ID комнаты проверяется как ограничитель маршрутизации; сам по себе он не доказывает членство в комнате.

Личная тайна, имя, инвентарь, заметки и задачи доступны владельцу и ведущему. У остальных игроков нет API получения этого листа. Холод, заражение и галлюцинации хранятся отдельно и исключаются из всех ответов игрокам, включая ответ на сохранение. От этих чисел не зависят текст состояния, CSS, симптомы или иные ответы игрокам. Симптомы отмечаются явно; скрытые числа сами их не изменяют. Ревизия листа может увеличиваться при действиях ведущего, но числовые значения скрытых полей не раскрываются.

Сервер хранит SHA-256 хеши случайных кодов и токенов; высокоэнтропийные коды не являются человеческими паролями. Сессия действует 12 часов без продления и хранится в `sessionStorage` iframe, отдельно по комнате и пользователю Owlbear. В URL, общих метаданных и `localStorage` сетевых токенов нет. Если браузер запрещает sessionStorage, вход работает до закрытия окна, повторное окно потребует кода. Для окон и других устройств состояние синхронизируется через сервер. Ротация кода отзывает прежний код и все его сессии; выход отзывает только текущую сессию.

Разворачивайте клиент и API на одном выделенном HTTPS origin без чужих скриптов. XSS на этом origin, расширения браузера с доступом к нему, доступ к устройству пользователя или разглашение кода/токена нарушают приватность этой учётной записи. Доступ администратора сервера/диска раскрывает данные всех персонажей: SQLite не шифрует их на диске. Защищайте диск и резервные копии, при необходимости используйте шифрование тома. Это не сквозное шифрование. Не публикуйте данные SQLite и вывод CLI.

API не включает CORS, принимает токены в Authorization, проверяет структуру и размеры данных, ограничивает частоту входов, отключает кеширование и выдаёт CSP, разрешающую встраивание в Owlbear. Не добавляйте `X-Frame-Options: DENY/SAMEORIGIN` на обратном прокси. Не отключайте TLS. Развёртывание рассчитано на один процесс Node с постоянным локальным диском, не на несколько реплик/serverless. После перезапуска rate-limit сбрасывается; для публичного сервиса дополните его лимитами обратного прокси.

Локальная проба — автономная демонстрация четырёх своих тестовых листов, без сетевых прав, ведущего и скрытых показателей. Её данные хранятся в localStorage с областью комнаты/пользователя, если открыт Owlbear, и доступны владельцу браузера. Прежнее общее хранилище прототипа `borey89_v2` автоматически не импортируется, чтобы не переносить чужие данные. Эта проба не используется как резервный путь при ошибке авторизации комнаты.

## Зависимости

На момент проверки официальный SDK 3.1.0 зависит от `uuid@9`. `npm audit` сообщает moderate advisory GHSA-w5hq-g745-h8pq о v3/v5/v6 с предоставленным буфером (и зависимом SDK). SDK в своих MessageBus/GenericItemBuilder вызывает v4 без буфера; серверная авторизация использует `node:crypto`. Принудительная подмена зависимости SDK не делалась. Следите за официальным обновлением и повторяйте `npm audit` перед публикацией.
