# Борей-89 · расширение Owlbear Rodeo 2.0

Интерактивные личные дела Охранника, Медика, Электрика и Механика в стиле прототипа 1989 года. Открываются кнопкой расширения в popover Owlbear (440 × 700) или кнопкой «Окно» в модальном окне Owlbear (1040 × 800). На узком экране карточки становятся в одну колонку, вкладки прокручиваются.

Два этапа реализации:

1. **Локальная проба:** официальный manifest и SDK, вкладки, здоровье 0–4, стресс 0–6, симптомы, добавление/удаление инвентаря, ФИО, личная тайна, заметки, задачи, четыре отдельные профессии, сброс и сохранение в браузере.
2. **Комнатная игра:** Node.js + SQLite, отдельные коды доступа, серверные права, синхронизация каждые 2 секунды, приватные поля ведущего и контроль конфликтов. Игрок получает только свой лист; ведущий — все четыре. Тайна доступна владельцу и ведущему. Холод, заражение и галлюцинации 0–10 приходят только ведущему.

Секреты не хранятся в общих метаданных Owlbear. Серверная авторизация основана на независимых кодах, а не на подделываемом клиентском сообщении о роли. Подробнее: [SECURITY.md](SECURITY.md).

## Локальный запуск

Требуется Node.js **24 LTS**, npm и постоянный диск. Встроенный `node:sqlite` не требует установки отдельного сервера БД. Команды выполняются в корне этого репозитория.

```sh
npm ci
npm run build
npm start
```

Откройте `http://127.0.0.1:3000` для локальной проверки и нажмите «Локальная проба». Это демонстрация без комнатной синхронизации и без режима ведущего. Чужие листы на сервере она не открывает. Для разработки с автообновлением оставьте `npm start` в первом терминале и выполните `npm run dev` во втором; Vite на порту 5173 перенаправляет `/api` на порт 3000.

Не используйте `vite preview` как сервер совместной игры: он не содержит API. Старое хранилище HTML-прототипа автоматически не импортируется.

## Создание комнаты и вход

1. Установите размещённое расширение в Owlbear по инструкции ниже. Откройте его в нужной комнате: форма покажет ID комнаты. Создать серверную комнату можно до подключения игроков.
2. На сервере выполните с тем же `DB_PATH`, что у работающего приложения:

   ```sh
   npm run room:create -- --obr-room ID_КОМНАТЫ_OWLBEAR
   ```

3. CLI выведет **пять секретных кодов**. Передайте код ведущего только ведущему, а коды профессий — соответствующим игрокам. Не копируйте этот вывод в репозиторий, общий чат, баг-репорт или публичный журнал CI. Повторное создание существующей комнаты завершится ошибкой, данные не сбросятся.
4. Каждый вводит свой код прямо в расширении. ID берётся из SDK автоматически и не редактируется. При проверке вне Owlbear его вводят вручную. Код не нужен для локальной пробы.
5. При изменении листа дождитесь надписи «Сохранено в комнате». Сохранение начинается через 450 мс после ввода; обновления от других окон/ведущего приходят в течение примерно 2 секунд при доступном сервере. Серверный лист сохраняется после перезагрузки, закрытия Owlbear и перезапуска сервера.

Сессия действует 12 часов. На другом устройстве или после истечения сессии введите код снова. Окна одного игрока в одной вкладке браузера используют sessionStorage; если браузер блокирует его в iframe, повторный вход потребуется в каждом окне. Личная тайна не сохраняется в браузере в сетевом режиме.

При параллельном изменении одного листа сервер возвращает конфликт и не перезаписывает свежую запись. В окне остаётся ваш черновик: скачайте его, затем загрузите серверную версию и перенесите нужные изменения вручную. Аналогично обработан обрыв связи при сохранении. Скачанный JSON может содержать личную тайну и, у ведущего, скрытые числа: храните его приватно. Автоматического импорта JSON нет. Если закрыть окно с несохранёнными данными, черновик может потеряться; не полагайтесь только на предупреждение браузера.

Администратор может отозвать потерянный или раскрытый код и все его сессии:

```sh
npm run room:rotate -- --obr-room ID_КОМНАТЫ_OWLBEAR --slot 0
npm run room:rotate -- --obr-room ID_КОМНАТЫ_OWLBEAR --slot gm
```

Слоты: `0` — Охранник, `1` — Медик, `2` — Электрик, `3` — Механик, `gm` — ведущий. Новый код выводится один раз; при потере выпустите следующий. Выход в интерфейсе отзывает текущую сессию.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

Если Chromium уже установлен, загрузка не нужна:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
```

API-тесты используют отдельные временные/оперативные БД. Браузерные тесты сами запускают сервер на 3100 с тестовыми кодами **только в оперативной памяти**; не запускайте `tests/ui-server.js` для реальной игры. Проверяются интерфейс 360 px, все вкладки и профессии, сохранение, три отдельных браузерных контекста, синхронизация, отсутствие скрытых данных у игрока, конфликт и обрыв сети. SDK тестируется в iframe через протокольный стенд: это не подтверждение установки в живой комнате Owlbear.

Перед публикацией проведите ручную проверку в настоящей комнате Owlbear с отдельными аккаунтами ведущего и двух игроков:

- Кнопка расширения открывает лист; «Окно» открывает его внутри Owlbear, без перехода на сайт.
- Игроки входят разными кодами и видят по одной профессии; ведущий — четыре. Правки здоровья, инвентаря и записей появляются у ведущего и владельца, переживают перезапуск.
- Изменение заражения и галлюцинаций не выдаёт игрокам чисел ни в интерфейсе, ни в ответах `/api/sheets`. Чужой тайны в их ответах нет. Подмена `slot` в PATCH даёт 403.
- Проверьте узкую панель, окно, выход, отзыв кода, параллельную правку и потерю сети. Проверьте используемые браузеры и их ограничения sessionStorage внутри iframe.

## Публикация

Нужен HTTPS-домен и хостинг **Node.js 24 с постоянным диском**. GitHub Pages и другие чисто статические хостинги подходят только для локальной пробы; комнатная игра требует API. Фронтенд и API публикуются на одном выделенном origin, в корне домена. Не размещайте SQLite в `dist`, `public` или общедоступном каталоге.

### Вариант с Docker

```sh
docker compose up -d --build
docker compose exec borey npm run room:create -- --obr-room ID_КОМНАТЫ_OWLBEAR
```

Контейнер работает от пользователя `node`, том `borey-data` сохраняет SQLite. Порт доступен только на `127.0.0.1:3000` хоста. Настройте на этом хосте HTTPS reverse proxy с действительным сертификатом; например, Caddy на хосте:

```caddyfile
borey.example.org {
    reverse_proxy 127.0.0.1:3000
}
```

Замените домен на свой и направьте на сервер DNS. Caddy автоматически получает сертификат при корректных DNS и доступных портах 80/443. `TRUST_PROXY_HOPS=1` в Compose предполагает **один** доверенный прокси, который корректно устанавливает X-Forwarded-For. Для другой сети адаптируйте настройку, не открывайте порт приложения напрямую в Интернет. Не добавляйте заголовок X-Frame-Options, запрещающий iframe: сервер уже задаёт frame-ancestors для Owlbear. Не отключайте HTTPS и проверку сертификатов.

Если сборка выполняется за доверенным TLS-прокси, передайте стандартные proxy build args и доверенный CA через временный BuildKit secret (CA не попадёт в образ):

```sh
docker build --build-arg HTTP_PROXY --build-arg HTTPS_PROXY --build-arg NO_PROXY \
  --secret id=npm_ca,src=/path/to/trusted-ca.pem -t borey-89-borey .
docker compose up -d --no-build
```

HTTP_PROXY/HTTPS_PROXY берутся из среды сборки. Укажите настоящий доверенный CA вашей инфраструктуры; не отключайте проверку TLS. При другом имени Compose-проекта используйте соответствующее имя образа вместо `borey-89-borey`.

В изолированной cloud-среде Docker DNS может отличаться от DNS основной машины. Если контейнеры не разрешают адрес доверенного прокси, настройте DNS Docker на сервере. Для диагностики Linux-сборки можно использовать `docker build --network=host`; при необходимости `--add-host ИМЯ_ПРОКСИ:ЕГО_ПРОВЕРЕННЫЙ_IP`, сохраняя исходное имя прокси и проверку сертификата. Эти настройки касаются сборки, а не публичного порта приложения.

### Без Docker

```sh
npm ci
npm run build
NODE_ENV=production DB_PATH=/var/lib/borey89/borey.sqlite TRUST_PROXY_HOPS=1 npm start
```

Каталог БД заранее создаёт администратор с правами только для пользователя процесса. Организуйте запуск через systemd/процесс-менеджер и тот же HTTPS reverse proxy. `npm start` по умолчанию слушает только 127.0.0.1:3000. Для CLI создания/ротации обязательно задавайте тот же DB_PATH. Запускайте ровно одну реплику на локальном диске; эфемерный/serverless-диск не подходит. Не кладите секретные коды в переменные сборки Vite.

### Установка в Owlbear

1. После развёртывания проверьте HTTPS-ответы `/manifest.json`, `/icon.svg`, `/`, `/api/health`; последняя точка должна вернуть `{"ok":true}`. Приложение должно отдаваться в корне домена, без префикса пути.
2. В управлении расширениями аккаунта Owlbear Rodeo добавьте своё расширение по URL `https://ВАШ-ДОМЕН/manifest.json`, затем включите его в нужной комнате. Манифест использует официальный `manifest_version: 1`; версия Owlbear 2.0 не означает `manifest_version: 2`.
3. Откройте кнопку «Борей-89 · Личное дело», скопируйте показанный ID для создания комнаты на сервере и войдите соответствующим кодом. Все участники используют один URL расширения и один сервер.
4. Выполните ручные проверки выше. Для обновления пересоберите приложение/образ, сохранив том; при изменении манифеста увеличьте его `version` и обновите расширение в Owlbear.

Домен, TLS и установка в живую комнату не создаются командами сборки. Никакие коды реальных комнат в репозитории не содержатся.

## Конфигурация и резервные копии

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DB_PATH` | `./data/borey.sqlite` | Постоянная SQLite БД, включая WAL/SHM рядом с ней |
| `HOST` | `127.0.0.1` | Адрес прослушивания; в Docker `0.0.0.0` |
| `PORT` | `3000` | Порт API и готового фронтенда |
| `NODE_ENV` | не задано | `production` включает HSTS и HTTPS-политику |
| `TRUST_PROXY_HOPS` | не задано | Число доверенных переходов только за известным прокси |
| `CHROMIUM_PATH` | не задано | Уже установленный Chromium для UI-тестов |

Ведущий управляет игрой через UI; администратор хостинга — кодами, доступом к диску и резервными копиями. Для простой согласованной копии остановите приложение, сохраните **весь каталог БД**, затем запустите приложение. Для Compose не удаляйте именованный том (`docker compose down -v` уничтожит данные). При восстановлении также остановите процесс, восстановите каталог с корректными правами и запустите ту же версию приложения. Резервная копия содержит личные тайны и хеши ещё действующих кодов/сессий; защищайте её как базу.
